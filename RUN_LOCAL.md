# RUN_LOCAL.md — steps to run on your machine

Things the cloud session can't do (no `data/raw`, no Atlas or Vercel access, no DuckDB
`spatial` download), listed per change in the order to run them. Newest at the bottom.
Tick a box when it's done locally.

## Multi-region refactor (PLAN.md, Phase R1)

### Before anything: get the branch

- [ ] `git fetch origin claude/amazing-maxwell-pztatq && git checkout claude/amazing-maxwell-pztatq`
- [ ] `npm ci`

### Step 1 — configs moved to `regions/nqn/` (`e611863`)

Nothing to run. Local edits to `pipeline/names.json`, `lakes.json`, `ign-overrides.json`
and the other region configs not yet committed must be redone in `regions/nqn/`.

### Step 2 — `--region` flag; `data/work` and `data/out` per region (`c9f7bfa`)

- [ ] Move the old work files once (the `mv` warns that it can't move `nqn` into itself; expected):
  ```sh
  mkdir -p data/work/nqn && mv data/work/* data/work/nqn/
  ```
- [ ] `data/out/reaches.ndjson` (gitignored, regenerated by `pipeline:export`) moves too:
  ```sh
  mkdir -p data/out/nqn && mv data/out/reaches.ndjson data/out/nqn/
  ```
- [ ] Check that nothing changed in the outputs: re-run the export and compare.
  ```sh
  npm run pipeline:export -- --region nqn
  git status --short data/out   # expected: no changes
  ```
- [ ] `npm run check`: the two DuckDB `spatial` tests that fail in the cloud should pass here.

### Step 3 — tiles per region in `public/tiles/<region>/` (`6c3f8c3`)

The committed tiles moved to `public/tiles/nqn/` (byte-identical). Checked in the cloud with
`next build` + `next start`: `/tiles/nqn/<hash>/rivers.pmtiles` answers 206 with
`max-age=31536000, immutable`, and the old `/tiles/<hash>/<file>` URLs still answer 206.

- [ ] `npm run dev`, open the map, and check that the rivers, mask, sub-basins, IGN layers and
      localities all draw, and the minimap shows rivers (no PMTiles 404s in the browser console).
- [ ] When you next rebuild tiles, use `npm run pipeline:tiles -- --region nqn`; it now writes
      to `public/tiles/nqn/`. If an old run left `public/tiles/*.pmtiles` at the top level,
      delete them (`git status public/tiles` shows them as untracked).
- [ ] After the next Vercel deploy: open the map and check in the browser's Network tab that a
      tile request to `/tiles/nqn/<hash>/…` returns 206 with the `immutable` header. The
      `DECISSIONS.md` Phase 8 note says this was never checked on Vercel.

### Step 4 — one Mongo database per region (`8e968bd`)

`nqn` keeps the `basin-explorer` database, so nothing needs reseeding and `.env.local` /
Vercel keep `MONGODB_DB=basin-explorer` (now the base name). Other regions will use
`basin-explorer-<id>`.

- [ ] Check the seed still targets the same database without writing anything new: the
      report names it.
  ```sh
  npm run seed -- --region nqn
  jq '{ok, region, db}' data/work/nqn/seed/report.json   # expected: ok true, db "basin-explorer"
  ```
- [ ] `npm run atlas:check` (or `-- --region nqn`) still prints `"ok": true` and `"db": "basin-explorer"`.
- [ ] Later, before Córdoba goes live: the read-only app user has `read@basin-explorer` only.
      Give it `read@basin-explorer-cba` too (Atlas → Database Access → edit user), or switch it to
      Atlas's "Only read any database" role. Then run `npm run atlas:check -- --region cba`.

### Step 5a — queries and the ask box take a region (`4e2d254`)

Every data query, the ask catalog (one in-memory catalog per region) and the ask cache key
(`ask:v2:<region>:…`) take a region; the routes still pass `nqn`. The cache key format
changed, so the ask box's Upstash cache starts empty once deployed: expected, entries
expire on their own (7 days).

- [ ] `npm run dev`: search a river ("limay", and a typo like "limai"), open a river, a
      sub-basin, a stream and a reach panel; ask "¿Qué río es más largo, Caleufú o Agrio?".
      All should behave as before.

### Step 5b — pages and API routes under `app/[region]/`, host → region in `proxy.ts` (`d15af69`)

`proxy.ts` rewrites every request to its host's region (`regions/hosts.ts`): a host whose
first label is a region id (`cba.example.com`, `cba.localhost:3000`) serves that region;
any other host, including `rionegrobasinexplorer.vercel.app` and plain `localhost`, serves
`nqn`. Public URLs don't change. Checked in the cloud with `next build` + `next start`:
pages 200 on any host, `/en`, `/es/map` and `/?r=limay` still redirect, `/xyz/map` 404,
icons, tiles and the MapLibre worker untouched, the OG image is built per region at
`/nqn/opengraph-image`. API routes answered 500 there only because the cloud has no
`MONGODB_URI`.

- [ ] `npm run dev`, then open both `http://localhost:3000/map` and
      `http://nqn.localhost:3000/map` (Chrome and Firefox resolve `*.localhost` on their own;
      Safari may not). Click a river, search, ask a question: the API routes must answer
      from Atlas as before.
- [ ] `npm run test:e2e` (Playwright, local only) — the URLs the tests use haven't changed.
- [ ] After the Vercel deploy: open the landing, the map, `/attributions` and a shared link
      such as `/?r=limay`; check `/api/health` returns `{"ok":true}`; share the landing URL
      in a link-preview tool (or check `og:image` in the page source) to see the OG image.

### Step 5c — the map reads its region on the client (`ed96bd4`)

`app/[region]/layout.tsx` provides the region (`components/RegionProvider.tsx`); the main
map and the minimap take their extent, bounds and tile URLs from it (`mapConfigFor`,
`tilePaths`). `pipeline/lib/map-config.ts` now reads `regions/<--region>/map.config.json`.
Every region must keep the same number of Visible Land levels (a test checks it).
Not checked in a browser in the cloud (project rule: no Chromium runs unless asked).

- [ ] `npm run dev`, open `/map`: the map opens on the basin, can't pan past the mask edge,
      draws every layer, and the minimap (desktop, Display panel) shows the basin and follows
      the view. The browser's Network tab shows tiles from `/tiles/nqn/<hash>/…`.
- [ ] `npm run pipeline:mask -- --region nqn` and `npm run pipeline:tiles -- --region nqn`
      still run; `git status public/tiles` shows no change.

### Step 6a — region strings in `regions/<id>/messages/` (this commit)

Fourteen strings that name the Río Negro basin (titles, map title, landing hero and
cards, ask examples, the dam caveat) moved from `messages/*.json` to
`regions/nqn/messages/*.json`, same keys, merged per request (`i18n/messages.ts`).
`proxy.ts` sends the region to `i18n/request.ts` in the `x-basin-region` header (always
overwritten, so a client can't pick it). Checked in the cloud with `next start`: titles,
hero and `/attributions` in both languages are unchanged, and the OG image renders.

- [ ] If you have uncommitted edits to `messages/*.json` touching those keys, redo them in
      `regions/nqn/messages/`. New shared strings still go in `messages/`; new strings that
      name a region go in every `regions/<id>/messages/` (a test checks every region has the
      same keys).
- [ ] `npm run test:e2e`: the specs now read `messagesFor("nqn", …)`.
